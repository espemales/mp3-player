# MP3 Player Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tauri-based MP3 player: single .exe, system tray icon, minimal floating mini-player, 8-band EQ with presets and per-track overrides.

**Architecture:** Tauri 2.x + React 18 + TypeScript. Rust backend handles file I/O, folder watching, and tray. WebView2 frontend handles audio via Web Audio API. JSON config in %APPDATA%/mp3-player/.

**Tech Stack:** Tauri 2.x, React 18, TypeScript, Vite, Web Audio API, notify-rs, tauri-plugin-store

**Spec:** SPEC.md

---

## Global Constraints

- Tauri version: **2.x** (stable)
- Output: single **`.exe`** via `tauri build` — no installer
- EQ gain range: **-12dB to +12dB** per band, clamped
- Window size: **400px x 64px**, frameless, always-on-top
- Supported audio: `.mp3`, `.flac`, `.wav`, `.m4a`, `.ogg`
- Config dir: **`%APPDATA%/mp3-player/`** (Windows)

---

## Review Focus

1. **Window transparency** — frameless window with rounded corners over transparent background; ensure WebView2 background is transparent so the CSS rounded corners show correctly over the desktop
2. **EQ gain clamping** — values from any source (preset, slider, saved track override) must be clamped to -12dB to +12dB before passing to BiquadFilterNode.gain
3. **File watcher resilience** — if a watched folder is deleted, the watcher must not crash; emit a notification and stop watching that folder
4. **Drag & drop** — accept both file drops and folder drops; recursive folder scan must be async and non-blocking
5. **Tray hide on close** — closing the window must hide to tray, not quit; only tray "Quit" menu item exits the app
